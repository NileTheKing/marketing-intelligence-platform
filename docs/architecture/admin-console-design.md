# 관리자 콘솔 디자인

Status: active

관리자 화면은 `console.css`와 `fragments/console_sidebar.html`을 기준으로 맞춘다.
참고 화면은 전체 개요(`global-dashboard.html`), 캠페인 관리(`admin.html`),
활동 대시보드(`dashboard.html`), 증분 효과(`incrementality.html`)다.

## 시각 기준

- 배경 `#f7f7f5`, 흰색 카드, 테두리 `#e7e6e2`, 카드 모서리 10px.
- 강조색은 `#2b5cd6`. 위험은 `--low`, 활성 상태는 `--ok`, 나머지 상태는 회색.
- Pretendard, 본문 13px, 페이지 제목 19px. 수치는 `.num`, 표의 숫자는 오른쪽 정렬.
- 왼쪽 공통 사이드바와 `.topbar`, 섹션 제목 `.cat`, 내용 `.card`로 구성한다.
- KPI는 `.kpis`, 차트는 `.card.panel`, 표는 공통 table 스타일을 쓴다.
- 버튼, 상태 표시, 툴바, 드롭다운, 기간 선택, 입력 필드와 모달은 `console.css`에서 공유한다.
- 그림자는 드롭다운에만 사용한다. 큰 아이콘, 이모지, 그라데이션과 색 배경 히어로는 쓰지 않는다.
- 새 문구는 한국어로 작성하고 나열에는 쉼표를 쓴다.

## 차트와 수치

Chart.js 4.4.1을 사용한다. 기본 막대는 `#dcdad4`, 강조할 막대는 파랑이다.
범례와 격자, y축을 숨기고 시간대 x축은 6시간 간격으로 표시한다.
금액 표기는 `global-dashboard.js`의 `formatWon`을 따른다. 1억 미만은 원 단위,
1억 이상은 억과 만원 단위를 쓴다. ROAS 100% 미만은 빨강, 매출이 없으면 `매출 없음`이다.
조회할 수 없는 데이터는 실제 0과 구분해 안내와 `-`로 표시한다.

## 동작 유지와 확인

스타일 개편에서는 요청 경로, 폴링 주기, 요소 id와 이벤트 연결을 유지한다.
이전 레이아웃을 제거할 때 `common.js` 등 기존 스크립트 의존성도 확인한다.
챗봇과 기존 폼에서 사용하는 Tailwind, Font Awesome은 유지한다.

로컬 Compose 프로젝트는 `docker`다. Core만 재빌드하고 `--no-deps`로 실행한다.
공유 MySQL과 Redis는 재생성하지 않는다. 기존 시연 데이터가 있으면 초기화하지 않는다.
1440px 폭에서 기준 화면과 각 화면을 비교하고, 목록 조회, 기간 변경,
폼 열기와 닫기, 수정 값과 유형별 입력 전환을 확인한다.

## 탐색 범위

- 캠페인 대시보드, 쿠폰, 행동 이벤트, 캠페인 생성·수정 폼과 활동 생성 화면은 공통 콘솔을 사용한다.
- 관리자 진입 `/admin`은 전체 개요로 연결한다. 데이터 API와 접근 권한 정책은 별개다.
- 코호트는 배치 분석용 보조 화면이다. 외부 데모 기본 탐색에는 추가하지 않는 것을 권장한다.
- 모니터링은 내부 운영 화면이다. 외부 데모에 공개하지 않고 기존 권한을 유지하는 것을 권장한다.
  두 화면은 이번 디자인 작업에서 개편하거나 권한·노출 정책을 변경하지 않는다.

## 2026-10-24 로컬 확인

- 1440px에서 전체 개요와 캠페인 관리 기준 화면을 비교하고, 캠페인 대시보드,
  쿠폰 목록과 생성·수정 팝업, 이벤트 목록과 생성 폼, 캠페인 생성·수정 팝업,
  활동 생성 화면과 활동 수정 팝업을 확인했다. 실제 시연 데이터로 조회하며 저장·삭제는 하지 않았다.
- 기간 변경과 SSE 재연결, 팝업 열기·닫기, 기존 수정 값,
  활동 이름 미리보기, 상품·쿠폰 검색, 쿠폰 지급 방식별 필수 입력 전환을 확인했다.
- 기존 관리자 데모 통합 테스트 4개가 통과했다. `/admin`의 개요 리다이렉트도 반영했다.
  테스트 JWT는 로컬 확인에만 사용하고 값은 기록하지 않았다.
- 화면 스크립트의 기존 `fetch` 요청 표현과 폼 요소 id를 대조했다.
  활동 생성 스크립트가 참조하는 `.lg:col-span-8` 클래스와 `header h1` 구조도 유지한다.
- 별도 후속 이슈: 로컬 시연 데이터의 증분 분석 API는 기존 HTTP 409를 반환한다.
  기존 쿠폰 활동 수정은 `Helpers.applyCouponEdit` 호출과 모듈의 공개 함수 위치가 달라
  초기화 오류가 발생한다. 두 문제는 디자인 개편 범위에서 기능을 바꾸지 않고 남겼다.
