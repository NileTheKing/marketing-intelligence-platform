# Experiment Evidence Workflow

Status: active

실험·테스트·성능 수치를 확인할 때 적용한다. 목표는 결과의 근거를 확인하면서 불필요한 로그 읽기와 재실행을 줄이는 것이다. 작은 단위 테스트에는 필요한 단계만 적용한다.

## 실험 설계 참고 사례

아래는 외부 사례에서 뽑은 비교 관점이다. Axon의 구현 사실이나 성과로 취급하지 않는다. 원문 메모는 Obsidian vault의 `_meta/백엔드_문제해결_모범사례.md`에 있다.

| 사례 | 비교 질문 | 함께 확인할 비용·경계 |
|---|---|---|
| 인덱스 | 인덱스 없음·단일·복합에서 실행계획과 조회 시간이 어떻게 달라지는가? | INSERT 시간과 인덱스 용량 |
| ArchUnit | 의도적으로 넣은 규칙 위반을 CI가 실제로 차단하는가? | 감지율과 부가 쿼리·API 성능 |
| 캐시 경쟁 | 같은 key의 조회·수정 순서를 강제로 재현했을 때 최신 값이 유지되는가? | 최종 캐시값과 남는 경쟁 조건 |
| AI 검토 큐 | 신뢰도 임계값을 바꾸면 자동 분류 정확도가 어떻게 달라지는가? | 사람 검토 큐 적체와 재시도·rollback |

## 기존 결과를 확인할 때

1. 먼저 답해야 할 질문과 필요한 수치를 적는다. 해당 실험의 결과 요약, 아티팩트 목록, 재현 명령을 찾는다. 파일 목록 확인에는 `rg --files`를 사용한다.
2. 수치를 인용하기 전에 비교 조건을 확인한다: 코드 버전, 실행 명령과 설정, 데이터 규모, 부하 형태, 측정 지점, 반복 횟수. 요약에 빠진 조건은 관련 스크립트·설정의 해당 부분에서 확인한다.
3. 원본 로그는 요약과 조건이 충돌하거나 실패 원인을 추적할 때만 읽는다. 먼저 `rg`로 지점을 찾고 해당 구간만 출력한다. 대용량 로그·JSON·실행 기록 전체를 대화에 출력하지 않는다.
4. 확인한 사실과 미확인 조건을 구분한다. 아티팩트만으로 답할 수 있으면 실험을 다시 실행하지 않는다.

## 새 실험을 할 때

1. 가설, 비교 대상, 통제 조건, 측정 지표, 성공·중단 기준을 실행 전에 짧게 정한다. 기존 실험을 반복한다면 기존 증거로 답할 수 없는 질문을 명시한다.
2. 실행 원본은 파일로 저장하고, 도구 출력에는 상태·핵심 지표·오류 구간만 남긴다. 실패했을 때도 관련 구간부터 확인한다.
3. 결과 요약에 실행 명령, 환경·코드 버전, 데이터·부하 조건, 반복 횟수, 수치, 원본 파일 경로, 한계를 기록한다. 측정하지 않은 효과나 조건이 다른 결과를 전후 개선으로 쓰지 않는다.
4. 정해 둔 질문에 답할 증거가 충분하면 추가 탐색과 선택적 재실행을 멈춘다.
